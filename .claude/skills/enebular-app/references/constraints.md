# enebular の制約と、そこから決まる設計

出典:
- クラウド実行環境（ZIP デプロイ）— https://docs.enebular.com/ja/GetStarted/ZIPFileDeployment.html
- データストア — https://docs.enebular.com/ja/datastore/overview

## E1. ハンドラは値を return し、レスポンスはバッファされる

クラウド実行環境（ZIP）は AWS Lambda ベース。ハンドラは `{ statusCode, headers, body }` を **return** する。

**帰結:**

- **SSE / ストリーミングは原理的に使えない。** 「途中経過を流す」設計は成立しない
- 長い処理をバックグラウンドで走らせる手段が無い。**別リクエストとして撃たせる**しかない
  - 起動リクエストは `202 Accepted` + `retryAfterMs` を返し、フロントが再送する
  - この規約はフロント側の `api.js` に最初から入れておく（[scaffold.md](scaffold.md) 参照）
- `timeout` の設定値が想定レイテンシより長いかを確認する

## E2. データストアはメインキー + サブキーの JSON アイテムストア

- サブキーは**数値か文字列のみ**
- **JOIN・二次インデックス・集計（COUNT / AVG / GROUP BY）は無い**

**帰結:** リレーショナル設計は使えない。アクセスパターン起点のキー設計にする。集計は書き込み時に事前計算する。

## E3. ZIP の形

- ルート直下に `index.js` と `package.json`（親フォルダで包むと動かない）
- `"type": "module"` **不可**（CommonJS 必須）
- 250MB 以下

**帰結:** pnpm の symlink 付き `node_modules` は載らない → **esbuild で単一 CJS にバンドル**する。
アプリ側の `package.json` は `"type": "module"` のままでよく、ZIP に入れる `package.json` は
`zip-package.json` として別ファイルで持つ（設定に引きずられて壊れないようにする）。

## E4. アクセス数の上限

- データストアのアクセス数に月次上限（フリー 10,000 回 / エンタープライズ 3,000,000 回）
- 1 アイテム約 350KB まで

**帰結:** アクセス回数がキャパシティのボトルネック。**1 論理単位 = 少数アイテム**に集約する。

## キー設計の原則

E2 と E4 から導かれる。新しいテーブルを起こすたびにここへ戻る。

### メインキーの先頭に所有者・テナントを含める

他人のデータはメインキーが一致せず 0 件しか返らない。実装ミスが「情報漏洩」ではなく
「データが見つからない」に着地する。**アプリ層のフィルタリングに頼らない。**

### リポジトリ層は生の `string` を受け取らない

`OwnerId` などの**ブランド型**だけを受け取る。文字列連結でキーを作るコードがコンパイルを通らなくなる。

```ts
export type UserId = string & { readonly __brand: 'UserId' }
export function toUserId(raw: string): UserId { /* 検証してから */ return raw as UserId }
```

### 1 論理単位 = 1 アイテムに集約する

ターンごと・イベントごとにアイテムを分けるとアクセス回数が線形に増えて E4 に当たる。

### 時系列サブキーは必ず数値型で作る

文字列で作ると範囲クエリが辞書順になり、**桁が変わった時点で壊れる**。

### 秘匿したいフィールドはテーブルごと分ける

`getItem` はアイテム全体を返すため、「カラムを選んで SELECT」に相当する防御が無い。
**テーブル分離が唯一の隔離手段。** 併せて公開型（`schemas.ts` / モノレポなら `packages/shared`）に
そのフィールドを定義しないことで、
コンパイル時にも防ぐ。

### 集計は閲覧時ではなく書き込み時に事前計算する

データストアに集計機能が無いため。

### `query` の `order` は `true` が降順

SDK 定義は false=ascending / true=descending。ULID をサブキーにすれば `true` が「新しい順」になる。

### テーブル ID はコードに書かない

環境変数（UUID）から解決する。未設定は**リクエスト単位のエラー**にする（起動は止めない）。
